## What Radix does here

Radix Primitives provides interaction and accessibility behavior; this repository styles those primitives with styled-components. Its role includes keyboard handling and focus management, while the site controls appearance. See the [official introduction](https://www.radix-ui.com/primitives/docs/overview/introduction).

| Package / repository wrapper               | Where visitors or staff encounter it                                                                                                                                 | Main regression concerns                                                                                 |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Dialog: `src/modules/Nav/MobileNav.tsx`    | Mobile navigation wherever the shared navigation is rendered                                                                                                         | Full-screen placement, focus entering and returning, Escape, scroll locking, navigation links            |
| Select: `src/components/Select/Select.tsx` | `/contact`; `/backoffice/bod` document filters and document modal; `/backoffice/access-management` and its user/policy forms; `/backoffice/graffix-requests` toolbar | Correct selected value, keyboard navigation, menu layering, accessible label, menu inside another dialog |
| Icons                                      | Select arrows/checkmarks, legacy U-Krew cards/directory                                                                                                              | Missing icons, alignment and contrast; icons do not supply dialog/dropdown behavior                      |

Do not attribute every overlay or tab to Radix. `BaseModal` imports `react-modal`; `TabCluster` imports `react-tabs`; `src/components/Tabs/Tabs.tsx` and `Expandable` contain their own implementations. Those still need styling regression checks, but are separate from the Radix upgrades.

## Findings from the current code

### Verified facts

1. **The existing fixes address a real v6 migration risk.** Commit `34245e01` adds `&` to self hover/focus/pseudo-element selectors in Tabs, Eyebrow, FluidContainer, ScrollCue, InstagramFeed, U-Krew cards/directory, and the recreation membership rule heading. Without `&`, a nested pseudo-selector can target descendants rather than the styled element. These fixes require checking each component's consumers, not just its source file.
2. **Expandable now passes the style props its CSS reads.** The working diff aligns `$isOpen`, `$indicatorRotation`, and related props between the trigger/header and CSS. Check open/close indicator rotation and persistent open fill as well as hover.
3. **Prop filtering is restored globally.** `_app.tsx` uses `StyleSheetManager` and `isPropValid` for string DOM targets while forwarding props to custom components. This reduces attribute warnings, but does not verify every wrapper preserves its className, ref, ARIA attributes, or event handlers.
4. **SSR styling remains configured.** `_document.tsx` collects `ServerStyleSheet` styles and seals the sheet; `next.config.js` enables the styled-components compiler transform. Configuration presence does not prove flicker-free rendering or hydration on every page.
5. **The v5-only type bridge is removed.** `src/types/styled-components-jsx.d.ts` explicitly said to delete it when moving to v6. Commit `91b08deb` deletes it, and the type-check passes without it. Its earlier presence was not a confirmed visual defect.
6. **The simple scan found no remaining line-leading bare pseudo-selectors in TSX except the intentional global `:root` in `_app.tsx`.** This does not cover all inline strings, helper-generated CSS, external styles, or selector intent; do not treat a search result as full CSS validation.

### Potential concerns requiring browser evidence

- `SelectTrigger` uses `*:focus`, which styles focused descendants rather than the trigger itself. Verify the trigger's visible keyboard focus; this is an existing selector worth checking, not a proven upgrade regression.
- Select uses a portal with `z-index: 1100`; BaseModal uses overlay `z-index: 1000`. Verify a dropdown inside a modal remains visible and interactive and that Escape closes the intended layer. Z-index alone does not prove correct focus behavior.
- Automatic vendor prefixes are not enabled on the app's `StyleSheetManager`. Some components already contain explicit WebKit declarations. Test the browsers the site supports before proposing a global prefix change.
- `styled(Typography)` consumers deserve attention to element choice and inherited typography. The board page already uses `forwardedAs: 'div'`; search results use `forwardedAs="span"`. Check resulting headings/text, layout, and hydration instead of assuming all polymorphic wrappers behave identically.
- `src/modules/UKrewCardList/Card.tsx` was fixed, but its presence/export does not establish an active page consumer. The legacy directory has a separate card implementation. Confirm which legacy U-Krew views remain in use before spending time on orphaned components.

## Repeatable checks and pass criteria

For each relevant page, record URL, revision, browser, viewport, state, pass/fail, screenshot and console evidence. Use a known-good pre-upgrade deployment as the comparison when available; content updates since then should not be mistaken for CSS regressions.

- **Initial render:** hard reload with cache disabled or network throttled, then navigate to the same page through the site. No unstyled flash attributable to missing server CSS, no hydration errors, and no styles disappearing after navigation.
- **Static layout:** typography hierarchy, colors, buttons/links, gutters, photo crop/scrim, pseudo-element decorations, and no unexpected horizontal scrolling. Check long headings and 200% zoom.
- **Interactive styling:** move the pointer over the whole intended target, including its padding; Tab through it; verify hover and keyboard focus affect the correct element. Selected/open/disabled states remain distinguishable.
- **Accordion:** toggle with keyboard and touch; verify indicator rotation and fill, `aria-expanded`, full open content, and closed content excluded from keyboard navigation.
- **Tabs:** check each panel and selected state, visible focus, narrow-width tab overflow and keyboard behavior. Verify URL/deep-link/Back behavior where the component implements it.
- **Radix layers:** open/close repeatedly, confirm accessible names, positioning, scrolling, focus containment where modal, and focus return. Test Select inside a modal separately from a standalone Select.
- **Motion:** use reduced motion for animated surfaces; ensure meaningful content and cues remain visible.
- **Console:** inspect unknown-prop, invalid HTML nesting, ref, hydration, Radix title/description, and styled-components warnings. A clean console alone does not establish correct appearance.
